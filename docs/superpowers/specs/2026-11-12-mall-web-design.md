# 商城前台与管理后台设计

用户于 2026-11-12 授权“按你的推荐直接做”，由实施者决定下面的默认值并直接实现。

## 目标与方案

在现有 Java 后端上完成可操作的中文购物与管理页面，用于端到端系统学习。买家端适配电脑和手机浏览器，后台优先电脑使用。保持单商家、实物商品、整单发货退款等现有规则。

选择 Vue 3 + TypeScript + Vite + Vue Router；后台采用 Element Plus，买家页面采用自定义响应式样式。使用一个 frontend 工程，storefront 与 admin 目录隔离页面，管理页面懒加载，共享 API 请求、类型、金额和日期工具。相比两个独立工程，减少初学阶段重复配置；相比服务端模板，能完整练习前后端分离。此方案是实施者选择，用户授权采用推荐方案。

## 范围

- 前台：商品检索、详情和规格选择、注册登录、购物车、地址、领券、结算、支付、订单、物流、确认收货、售后、个人资料及密码。
- 后台：登录、统计、分类品牌规格、商品与 SKU、库存、优惠券、订单和发货、售后、会员、账号角色权限、任务重试及审计。
- 接口仍返回直接 DTO；请求层处理空响应、ApiError、401、403、网络错误。两种身份使用独立会话存储；后端始终负责授权。
- 后台补充当前身份、角色权限与账号角色读取，以支持真实权限导航和编辑回显。
- 本地模拟支付新增仅 local/test 且开启模拟渠道时存在的买家接口，必须校验支付单归属；不向浏览器提供开发密钥。物流模拟由具备发货权限的管理员触发。
- 下单使用稳定幂等键，结算变更废弃报价；网络重试沿用请求，价格变化要求重新确认。HTTP 202 表示受理，支付结果轮询，离开页面停止轮询。
- 金额用整数分传输、元展示，ID 保留字符串；时间显示北京时间。商品图片仍使用后端支持的 HTTP(S) 地址，无图片时显示本地占位图。

## 视觉与交付

前台使用奶白背景、深绿色与暖橙强调色，清晰的商品卡片与结算层次；后台使用侧栏、面包屑标题、表格和表单。所有页面提供加载、空状态、错误和重试入口。禁用重复提交，危险操作二次确认。

不增加真实支付、文件上传、短信、评价、推荐算法或生产上线。开发服务仅监听本机；Vite 代理后端 API，生产部署文档说明同源反向代理与 HTTPS。
