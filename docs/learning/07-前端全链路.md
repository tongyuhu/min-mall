# 从页面走到数据库：商城前端学习路线

## 启动与入口

沿用 README 的步骤启动 Docker、后端和本地种子数据。另开 PowerShell，在仓库根目录运行 `./scripts/start-web.ps1`。首次会执行 `npm ci`，依赖版本由 `frontend/package-lock.json` 锁定。需要 Node.js 22.12 或更高版本。

- 买家商城：http://127.0.0.1:5173
- 商家后台：http://127.0.0.1:5173/admin
- 后端：http://127.0.0.1:18080

买家可以自行注册；已有演示账号为 `demo_buyer`，后台账号为 `admin`。密码使用本地 `.env` 首次初始化时的 `MALL_DEMO_PASSWORD` 和 `MALL_ADMIN_PASSWORD`，页面不内置密码。修改环境变量不会重置已创建账号。

## 从哪里开始读

1. [入口与路由](../../frontend/src/router.ts)：页面懒加载、买家登录守卫、管理员权限守卫。
2. [共享请求](../../frontend/src/shared/api.ts)：`api<T>(scope, path, options)` 返回接口 DTO。`scope` 决定 `/api/v1` 或 `/admin/v1` 前缀以及会话。200/201/202 只表示 HTTP 成功，支付业务成功仍判断 `status === 'SUCCEEDED'`。204/空体返回 undefined。错误读取 message 和 traceId，401 仅清理对应身份，403 保留登录。
3. [会话](../../frontend/src/shared/session.ts)：买家和管理员各自存放在 sessionStorage，仅当前标签页生命周期内保存。令牌不是 JWT，不自行解析，权限来自后端 `/admin/v1/auth/me`。前端菜单控制是交互提示，后端权限校验才是安全边界。
4. [商品页](../../frontend/src/storefront/ProductPage.vue) → [购物车](../../frontend/src/storefront/CartPage.vue) → [结算](../../frontend/src/storefront/CheckoutPage.vue) → [订单](../../frontend/src/storefront/OrderPage.vue)。先熟悉这一条主链，再阅读售后和管理模块。
5. [管理端商品编辑](../../frontend/src/admin/ProductsPage.vue)：从 editor 接口获取真实 SKU 规格值 ID，已有 SKU 规格不可改，删行代表停用，新增商品还需要库存调整和上架。

## 一次下单发生了什么

购物车将选中行 ID 交给 `/cart/selected`，后端校验归属和有效性，返回 SKU/数量。结算页读取地址和优惠券，POST `/checkout` 得到金额和 fingerprint；界面只展示后端报价，不自行决定支付金额。

提交订单时携带 `Idempotency-Key` 和原始 checkout、quoteFingerprint、fromCart。后端 OrderController → OrderService → CheckoutService 重新锁定并校验价格、地址、库存、优惠券，成功后保存订单快照。相同报价的网络重试使用原幂等键；收到冲突需重新计算并由用户确认。金额统一以整数分传输，展示层才转换为元；ID 保持字符串，避免 JavaScript 大整数精度损失。

创建支付单返回 202，页面展示处理中并轮询，不能收到 202 就显示付款成功。本地模拟按钮调用 `/api/v1/simulation/payments/{no}/success`：服务端先校验当前买家拥有该支付单，再通过模拟网关产生异步通知。原有支付状态机处理通知并更新订单。页面离开时停止轮询；不把 `MALL_SIMULATION_KEY` 提供给浏览器。

## 管理与售后链路

管理员登录后从 `/auth/me` 获取身份和权限列表。每次进入后台路由重新获取权限，菜单和按钮按权限展示。角色和账号编辑必须回显服务端当前配置，避免把未加载的权限当作空数组覆盖。

订单管理 → 订单详情 → 填写承运商和运单号 → 发货；后台可以触发本地模拟送达并同步轨迹。买家确认收货后申请售后，后台审核同意，买家寄回填写退货物流，后台确认验收，退款异步完成。任务异常可在后台任务页面查看，只有 MANUAL 任务且有 task:retry 权限时才显示可用重试按钮。

## 工程组织与选择

`frontend/src/storefront` 是买家页面；`admin` 是管理页面；`shared` 是类型、金额时间、请求与反馈组件。当前使用 Vue 响应式组合函数管理局部状态和少量共享身份，不为暂不需要的跨页缓存额外引入 Pinia。Element Plus 仅随管理端懒加载，买家端使用自定义样式。

商品图片支持 HTTP(S) URL，没有文件上传服务时不伪造上传按钮。无图显示本地绘制的“商品示意”图，带有明确标识；不把占位图当作实拍。所有样式使用本地字体回退，不依赖外部字体服务。

## 验证与调试

```powershell
cd frontend
npm test
npm run typecheck
npm run build
npm run format:check
npx playwright install chromium
# 已启动后端和前端；在需要真实交易测试时先导入根目录环境：
. ../scripts/import-env.ps1
npm run test:e2e
```

浏览器测试会创建独立买家账号并写入真实学习环境订单。测试输出、截图、追踪包位于被 Git 忽略的 `frontend/test-results` 和 `playwright-report`；可能包含会话信息，不要对外分享原始追踪文件。报告明确区分已运行、跳过和失败，不把类型检查当成业务验收。

- 401：检查当前身份是否过期，重新登录。修改密码/启停账号会使旧会话失效。
- 403：检查后台权限。禁止通过改前端菜单绕过服务端校验。
- 409：查看 message，可能是库存不足、报价变更或订单状态不允许操作。
- 支付长期处理中：检查后端 `mall.jobs.enabled`、后台任务和应用日志。请求受理不代表业务完成。
- 页面能开但 API 失败：确认后端 18080 运行；Vite 代理只转发 API，不代理开发密钥接口。
- 编辑后的页面显示旧内容：查看网络请求和 HMR；生产构建需重新生成 dist。

## 部署边界

`npm run build` 生成静态文件 `frontend/dist`。正式部署需要由 Nginx 等服务提供静态文件并配置 SPA fallback 到 index.html；`/api/v1/` 与 `/admin/v1/` 反向代理后端，API 404 不应回落为 HTML。两端使用同源 API，避免放宽后端 CORS。部署还需 HTTPS、真实渠道和环境安全配置，当前交付不等于生产上线。`vite preview` 仅用于本地构建预览，不能替代正式 Web 服务。

## 练习

1. 从购物车数量变更一路追踪到 CartService 和 SQL，解释为什么不能只修改浏览器数字。
2. 给一个运营角色去掉库存权限，观察侧栏、路由和直接 API 请求三个层面的结果。
3. 在已确认报价后修改商品价格，再提交订单，观察 409 和重新确认流程。
4. 模拟支付失败再成功，观察同一支付单如何恢复，以及订单何时才变为待发货。
5. 查看订单 JSON 中的商品快照，解释为何后台改商品标题不会改变历史订单。
